# Фазы 17–21 — целевая маршрутизация (rule/unify/local/compose)

Главная архитектурная партия проекта: один универсальный контракт
Редактора заменён маршрутизацией по классу правки. Ф17 (мелкие
починки), Ф19 (рамка «ты автор» для переписываний), Ф19-бис (третий,
незнакомый корпус `battery`), Ф20 (составные правки `compose`) —
закрыты, с остаточными пунктами контроля замером (перенесены в открытую

и НИ РАЗУ не окупился по правилу «меньше трёх ничего не доказывает»**;
решение принять/откатить не вынесено, отложено владельцем до финального
прогона (см. открытую работу). Ф21 (чистка мёртвого кода) не начата.

### Ф18. Лексический контракт: модель решает, код исполняет (главная партия)

Класс «сделай одинаково по всему документу»: унификация термина (c5, c7,
c11), форматы дат (c8), числа (c4). По замеру w12 — самый большой источник
провалов и единственный источник лжи. Принцип — инвариант 1, доведённый до
конца: модель отвечает только за РЕШЕНИЕ («какие пары заменить»), всю
мутацию и весь вердикт делает код.

- [ ] Навигатор: третий маршрут `unify` рядом с `rule`/локальным — «правка
      требует одинакового написания/формата ПО ВСЕМУ документу». В промпт —
      положительные примеры (термин четырьмя написаниями; годы тремя
      форматами; числа через точку → через запятую) и отрицательный:
      «замени слово в одном-двух названных местах» — это local, не unify.
- [ ] Один вызов модели (без кластеров): инвентарь вариантов с частотами
      (источники и счёт — как в `_variant_inventory`, переиспользовать) +
      полный текст правки → `{"pairs": [["старое","новое"], ...],
      "note": "..."}`. Пустые `pairs` + note — честный отказ.
- [ ] Исполняет код: пары сортируются по УБЫВАНИЮ длины `old` (иначе
      «Bi-encoder» перепишет внутренность «Bi-encoders»), замена — по
      границам слов, по всему документу, машинерией `_op_replace_all`
      (расширить словограничным вариантом поиска — `find.by_regex` уже есть).
- [ ] Вердикт выносит КОД, Проверяющий-LLM на этом пути не зовётся: после
      применения каждый не-канонический `old` ищется словограничной
      регуляркой по всему документу. Ноль вхождений всех `old` → `done`
      с отчётом «заменено N вхождений M вариантов»; иначе — откат снимка
      и честный отказ с перечнем оставшихся. Счёт и есть файл: инвариант 5
      выполняется сильнее, чем мнением модели.
**ЗАМЕР w13 (2026-07-28): партия в первом виде НЕ ПРИНЯТА.** Оценщик 15 → 13,
`done` 26 → 25, Э 79% → 63%, и вернулась ложь ровно там, ради чего партия
делалась: ColBERT 7 — `done` «заменено 3 вхождений 3 вариантов» при
неперекрытом маркере оценщика. Четыре дефекта, все вытащены из журналов
прогона, а не предположены:

1. **Вердикт считал не то.** `_run_unify` проверял, что исчезли те `old`,
   которые НАЗВАЛА модель, а не варианты, которые посчитал код. Модель на
   c7 выдала пары `Single-Vector Bi-encoders → Bi-encoder`, `Bi-Encoders →
   Bi-encoder` и разрушительную `Single-vector → Bi-encoder` (прилагательное
   в термин), а неназванные написания остались в файле — и код сказал `done`.
   Обещание «вердикт выносит код» не выполнялось: код верил списку модели.
2. **Канон, содержащий вариант, ломал проверку.** Математика 5: канон
   `«Человек, который познал бесконечность»` (в кавычках) содержит старый
   вариант, тот находится и после верной замены → «остался вариант» и откат
   правильной правки.
3. **Промпт Навигатора сдвинул классификацию `rule`.** В w12/w12b Математика
   2 и 6 давали `rule=None`; после добавления абзаца про `unify` — обе
   `rule="typography"`. Ушли по пути rule, нормализация поправила посторонний
   двойной пробел, Проверяющий верно сказал «это не та правка», и обе упали
   из `done/pass` в `rolled_back/fail`.
4. **Дыра пути rule, вскрытая тем же случаем.** Fallthrough на локальный путь
   срабатывает ТОЛЬКО при пустом diff нормализации. Изменила постороннее —
   правка умирает откатом, не получив ни одной настоящей попытки.

Что партия дала: ColBERT 11 (`failed` → `done`), ColBERT 14 (`failed` →
`rolled_back`), Математика 16 (`rolled_back` → `done`) — все три без маркера
оценщика. Проигрыши подтверждены оценщиком, выигрыши — нет; значит по мерилу
проекта это чистый минус. Чинится партией Ф18-бис (те же четыре пункта),
после неё — повторный полный замер. Если и он не даст прироста, маршрут
`unify` откатывается целиком.

**ЗАМЕРЫ w14 и w15: маршрут доведён до уровня w12, но прироста НЕ дал.**
w14 (после Ф18-бис): подтверждено 13, лжи 0, Э=68%. w15 (после Ф18-тер):
подтверждено **16 — лучшее число за проект**, но одна ложь, Э=79% — ровно
столько же, сколько у w12 без всякого `unify`. По правилу «прирост меньше
трёх ничего не доказывает» это НОЛЬ.

Что дали три замера поимённо:
- w14 отменил два решения Ф18-бис. Приоритет `unify` над `rule` сломал
  ColBERT 6 (кавычки) и Математику 1 (пробелы) — обе делались нормализацией.
  Порядок вернули; от неверного `rule` защищает fallthrough после отката
  Проверяющего, и Математика 2 и 6 вернулись в `done/pass` именно им.
- Отказ «модель не выбрала единый канон» тоже был потерей: ColBERT 4, 12 и
  Математика 5 в w12 делались локальным путём. Теперь пары без единого
  канона — сигнал «это не унификация», правка уходит на локальный путь.
  ColBERT 4 после этого впервые за проект прошла оценщика.
- Ложь ColBERT 7 в w15 вернулась, и её корень назван точно: **инвентарь
  вариантов — не скан документа, а список цитат из текста правки плюс якоря
  Навигатора** (`_variant_counts` строится из `_literals` и `anchors`).
  В документе осталось «Single-Vector» с большой V, которого никто не
  процитировал: в инвентаре его нет, значит проверка остатка его не искала,
  и код честно отчитался по своему неполному списку. «Вердикт выносит код»
  сильнее мнения модели ровно настолько, насколько полон инвентарь.

Решение НЕ принято и НЕ откачено: w15 не хуже w12, а обещанный выигрыш
маршрута — в накопительном режиме, где документ меняется под ногами
(изолированный режим этот класс правок и так вытягивает локальным путём).
Следующий шаг — накопительный прогон обоих корпусов на текущем коде против
накопительного w12 (74%, подтверждено 15). Правило решения записано заранее:
прирост есть — маршрут принимается, нет — откатывается целиком, вместе с

### Ф19. Рамка переписывания: автор, а не автозамена

### Ф20. Составные правки: один вызов вместо слепых кластеров

- [x] Навигатор: признак `compose` — правка строит одно целое из нескольких

      слияния окон внутри `_cluster` (`p - around <= cur_end`) при таком
      `around` истинно для ЛЮБОЙ пары резолвленных id — `_cluster`
      гарантированно возвращает один-единственный кластер из всех целей, в
