# Регламент сессии (docx-editor)

Ты — строитель этого проекта. Приоритеты не обсуждаются: они зафиксированы
в [BUILD_PLAN.md](BUILD_PLAN.md), секция «Очередь работ». Общение — по-русски.

Архитектор (Opus) правит BUILD_PLAN.md и ревьюирует фазы. Строитель правит
код. Строитель BUILD_PLAN.md не переписывает — только отмечает `[x]` и
дописывает находки в секцию своей фазы.

## Главное правило: минимум кода

Этот проект — вторая попытка. Первая утонула в 3200 строках, из которых
1800 были демо, и отлаживать это стало невозможно. Поэтому:

- Пиши наименьший код, который решает поставленный пункт. Если написал 200
  строк там, где хватило бы 50, — удали и напиши 50.
- Никаких абстракций с одним вызывающим. Ни Factory, ни Registry, ни
  Manager, ни базовых классов «на будущее». Класс — только если функции
  не хватает. Dataclass — только если dict не хватает.
- Никаких опций конфигурации для значения, которое не меняется.
- Дублирование дешевле неправильной абстракции. Обобщай на ТРЕТЬЕМ повторе.
- Ни одного .md-файла по своей инициативе. Ни ARCHITECTURE, ни SUMMARY, ни
  отчётов. README трогай, только если изменился способ запуска.
- Перед тем как добавить код, проверь, не решается ли задача удалением кода.

Ответ по умолчанию на «сделать ли это расширяемым» — **нет**.

## Язык

Задание тебе и твой отчёт архитектору — по-английски (русский стоит вдвое
больше токенов, а этот трафик повторяется на каждой фазе). Всё остальное
остаётся русским, и это не стилистика, а требования:

- тексты ошибок валидатора — их читает модель, чтобы исправиться, и запрос
  пользователя тоже русский;
- отчёт пользователю о правках;
- сообщения коммитов, `BUILD_PLAN.md`, `CLAUDE.md` — их читает владелец.

Комментарии и докстринги в коде — по-русски, как в уже написанных файлах.

## Инварианты (нарушать нельзя)

1. **LLM — последнее средство.** Всё, что решается детерминированно —
   поиск, нормализация текста, применение патча, проверка структуры, —
   делает код. Модель отвечает только за понимание языка и смысла.
2. **Документ правится на месте.** Никакой сериализации «граф → новый
   docx»: она уничтожает форматирование, нумерацию, поля и стили. Патч
   применяется к живым lxml-элементам исходного документа.
3. **Модель не видит документ целиком.** В контекст идёт локализованный
   фрагмент. Полная карта документа в промпте — ошибка архитектуры,
   а не оптимизация «на потом».
4. **Модель предлагает — код проверяет.** Ни один патч не применяется без
   валидации (id существует, `old != new`, `old` реально есть в блоке).
   Ни одна правка не считается выполненной без проверки результата.
5. **Отчёт не врёт.** «Сделано» подтверждается вердиктом проверки, а не
   тем, что функция не бросила исключение. «Не смог» и «отказался, потому
   что…» — валидные и уважаемые исходы. «Готово» без доказательства =
   переоткрытие пункта.
6. **Ошибки громкие.** Никаких `try/except`, глотающих ошибку и
   возвращающих значение по умолчанию. Не может работать — пусть падает.

## Как закрывается пункт плана

- Пункт закрыт только демо в `examples/` с `assert`'ами: демо обязано
  УПАСТЬ, если поведение сломано. Демо, печатающее числа без проверки, —
  иллюстрация, а не приёмка.
- Перед коммитом: `.venv/bin/python examples/run_all.py` зелёный.
- Демо — минимальное. Не пиши 500 строк демо на 100 строк кода: проверяй
  то, что может сломаться, а не то, что константа равна себе.
- Коммит на каждый закрытый пункт, сообщение по-русски: «Ф3: что сделано».

## Находки по ходу

- Баг в уже сданном — чинится СРАЗУ, до продолжения текущего пункта, в той
  фазе, которой он принадлежит (переоткрой чекбокс: `[x]` → `[ ]`).
- Несогласованность контракта, на который опирается текущий пункт, —
  сначала чинится контракт, потом продолжается пункт.
- Идея или расширение — строкой в BUILD_PLAN, НЕ в код. Никакого «раз уж
  я здесь, заодно сделаю».
- Вопрос архитектору задаётся, только если решения нет ни в плане, ни в
  коде, и выбор необратим. Всё остальное — выбирай сам и фиксируй письменно.

  живой вызов идёт 4–9 секунд и делает прогон недетерминированным, а это
  вопрос отлаживаемости, а не денег.
